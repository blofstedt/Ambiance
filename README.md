# Ambient Canvas

> **Working with an AI assistant on this repo?**
> Read **[CLAUDE.md](CLAUDE.md)** first. It contains a routing map showing which
> files to open for which kind of change, so you don't have to read everything.

A Google TV app that turns an idle television into a piece of framed art, and
matches that artwork to the actual light in the room using an ESP32 ambient
sensor.

The sensor reports illuminance (lux), correlated colour temperature (Kelvin) and
motion. The TV uses those readings to set picture brightness and warmth, to
blank the screen when the room is empty or dark, and to learn your preferences
per lighting condition — adjust the sliders once in evening lamplight and it
remembers that for every future evening.

## Repository layout

| Path | What it is |
| --- | --- |
| `src/` | React + TypeScript TV app |
| `src/lib/` | Framework-free logic: sensor protocol, discovery, profiles, weather |
| `src/hooks/` | Stateful behaviour: settings, sensor network, display state, rotation |
| `src/components/` | Presentation |
| `firmware/` | ESP32 sketch for the sensor |
| `android/` | Capacitor Android project, including the TV screensaver service |
| `mock/` | Mock sensor implementing the full firmware HTTP contract |
| `tests/` | Regression tests for the logic layer |

## Running the app

**Prerequisites:** Node.js 20.19 or newer.

```bash
npm ci
npm run dev
```

Open http://localhost:3000.

You do not need an ESP32 to develop. Start the mock sensor in a second terminal:

```bash
npm run mock:sensor
```

Then in the app open **Adjust Settings → Sensors & Telemetry**, enter
`localhost:8080` in the manual address field and press Add.

The mock reproduces the firmware's real failure modes, which is the point of it:

```bash
npm run mock:sensor -- --secured          # password already rotated
npm run mock:sensor -- --paired           # already paired to another TV (409)
npm run mock:sensor                       # factory password still set (428)
```

## Building for Android TV

```bash
npm run android:prepare   # builds the web bundle and runs `cap sync android`
npm run android:open      # opens Android Studio
```

`cap sync` is not optional. `android/settings.gradle` includes
`:capacitor-cordova-android-plugins`, and that directory is generated by sync —
Gradle configuration fails on a fresh clone without it.

Signing for a release build is driven entirely by environment variables, so no
keystore or password is ever committed:

```bash
export ANDROID_KEYSTORE_PATH=/path/to/release.jks
export ANDROID_KEYSTORE_PASSWORD=...
export ANDROID_KEY_ALIAS=...
export ANDROID_KEY_PASSWORD=...
export ANDROID_VERSION_CODE=42
export ANDROID_VERSION_NAME=1.0.0

cd android && ./gradlew bundleRelease
```

`minSdkVersion` is **26**. Launcher assets are vector-only adaptive icons so the
repo stays free of binaries, and adaptive icons require API 26. See
`android/BINARY_FREE_SETUP.md`.

## The sensor

Flash `firmware/ambient_sensor.ino` to an ESP32 with a TCS34725 colour sensor
and a PIR motion sensor.

| Pin | Purpose |
| --- | --- |
| I²C (SDA/SCL) | TCS34725 |
| GPIO 27 | PIR motion output |
| GPIO 14 | TCS34725 LED (driven very dim) |
| GPIO 26 | Factory reset button to ground, hold 8s |

### First-time setup

1. Power on. The sensor opens a Wi-Fi setup portal named **Ambient Setup**.
2. Join it from a phone and give it your home Wi-Fi credentials and a room name.
3. It reboots onto your network and advertises itself over mDNS as
   `ambient-<mac>.local`.
4. In the TV app, open **Adjust Settings → Sensors & Telemetry** and press
   **Rescan**.
5. **Set a password.** The sensor ships with `admin` / `changeme` and will
   refuse to pair, accept OTA, or factory reset until you replace it. The app
   walks you through this.

### HTTP API

| Method | Path | Auth | Notes |
| --- | --- | --- | --- |
| GET | `/api/status` | none | Live telemetry and device state. **This is the endpoint the app polls.** |
| GET | `/ui` | none | Local admin page |
| POST | `/api/name` | basic | Rename |
| POST | `/api/pair` | basic + rotated password | `409` if paired elsewhere |
| POST | `/api/unpair` | basic + rotated password | |
| POST | `/api/admin-password` | basic | Minimum 10 characters |
| POST | `/api/factory-reset` | basic + rotated password | |
| POST | `/api/ota` | basic + rotated password | Requires `X-Firmware-Version` and `X-Firmware-SHA256` |

`GET /` redirects to `/ui`. Do not poll it for JSON.

### Security boundary

This device speaks **plaintext HTTP on your local network**. The admin password
stops other devices on the LAN from reconfiguring it; it does not protect
against anyone who can already capture that LAN's traffic. The password is
stored as a salted SHA-256 hash, never in plaintext. Do not port-forward to this
device or expose it to the internet.

## Development

```bash
npm run verify        # typecheck + lint + test + build. Run before pushing.
npm run typecheck
npm run lint
npm run test
npm run format
```

TypeScript runs in `strict` mode with `noUncheckedIndexedAccess`.
`react-hooks/exhaustive-deps` is an **error**, not a warning — several of the
worst bugs in this app's history were stale-closure and missing-cleanup faults
in `useEffect`.

Everything under `src/lib/` is deliberately free of React and of native imports
so it can be unit-tested directly and reasoned about in isolation.

## Privacy

Location is requested **only** when you enable the weather overlay, and only to
fetch local conditions. See [PRIVACY.md](PRIVACY.md).

There are no analytics, no telemetry upload, and no accounts. Sensor readings
never leave your local network.
